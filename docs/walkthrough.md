# From a returned shoe to a pilot decision

## 1. Understand the job

Imagine it is February 2026. Merchandising has one small budget for improving product listings. Finance wants to know which issue costs most and how much the fix must achieve to pay for itself. Your deliverables are a ranked list for merchandising and a cost scenario for finance. The data comes from a seeded simulation, making the case reproducible and shareable.

## 2. Read the records

| File | Grain and key | Fields to know |
| --- | --- | --- |
| catalog.csv | One product per sku | Product name, category, list price and inventory cost in euro cents |
| sales.csv | One shipped line per line_id | Shipment date, SKU, Web or Store, quantity and realized unit price after discount |
| returns.csv | One accepted unit per return_id before duplicate export rows | Original line, receipt date, reason, restock/write-off decision and handling cost in cents |
| cohorts.csv | One shipment month × category × product × channel | Shipped/returned units, refund, initial margin and erosion. Monetary columns ending in _c use cents |
| opportunities.csv | One product × channel × reason among returns | Event count, erosion in cents, descending dense rank and percent of total erosion (0–100) |

Run the five commands in the README. Open the raw files first. A sales line can contain three units and receive several one-unit return events. Joining all events directly to sales and then summing shipments would count a multi-return line more than once. In model.sql, follow the by_line CTE. It collapses events to one row per line before the left join, preserving sales with zero returns.

## 3. Follow one transaction

Find return R00001 in returns.csv. Its parent is L000011, a store sale of a City sneaker. The customer receives €69.00. The item is restocked at €29.00 inventory cost, and handling costs €6.50. Margin erosion is €69.00 − €29.00 + €6.50 = **€46.50**. A write-off for the same sale would erode €75.50. Refunds measure cash returned to customers. Erosion measures the change from the margin expected when the goods shipped.

Open the database and run:

```sql
SELECT return_id, line_id, shipped, received, disposition,
       refund_c / 100.0 AS refund_eur, erosion_c / 100.0 AS erosion_eur
FROM events WHERE return_id = 'R00001';
```

## 4. Build a fair comparison

A December shipment returned in January still counts against December. This case observes all shipments for the full 30-day window. In a live monthly refresh, mark recent cohorts provisional until their window closes. Calculate each rate as total returned units divided by total shipped units for the selected group. Averaging monthly percentages gives low-volume months too much influence.

Web returns reached 11.26% and store returns reached 7.20%. Different product mixes can explain part of this gap. Use the product/channel cut before attributing the difference to the channel itself. To investigate fit, inspect the original reasons and product sizes. Size and customer feedback would be additional data requests in a real pilot.

## 6. Put a price on the decision

Open reports/Returns-review.xlsx. The Decision tab looks up the first-ranked issue. The model assumes an avoided return keeps the original sale, the average avoided return has the group's historical cost and annual volume is stable.

| Relative reduction | Gross avoided erosion | Annual pilot cost | Net annual benefit |
| ---: | ---: | ---: | ---: |
| 10% | €1,418.30 | €1,500.00 | −€81.71 |
| 15% | €2,127.44 | €1,500.00 | €627.44 |
| 20% | €2,836.59 | €1,500.00 | €1,336.59 |

Amounts are independently rounded from unrounded calculations. For a 10% reduction the exact net is −€81.705. Change B15 and B16 to explore the trade-off. A 15% relative reduction means preventing 15% of this targeted exposure. It does not mean a 15-percentage-point drop in the overall return rate.

For a fresh snapshot replace the data rows on Drivers and Cohorts with matching CSV columns, keeping the headers. If the row counts change, resize each table and extend the bounded ranges in the Decision formulas. Recheck total erosion and returned units against SQL. In the supported artifact-tool authoring environment, running the workbook builder from the repository root updates these bounds automatically.

## 7. Design the follow-up

Randomize eligible trail runner product-page visitors between the existing guide and a revised guide with foot measurements. Keep assignments stable per visitor. Predefine the primary outcome as fit-return erosion per eligible visitor. Track conversion and contribution per visitor as guardrails because a guide might deter purchases. Determine sample size from event rates and a minimum worthwhile effect, then wait for the return window to close. Roll out only if the expected annual benefit covers ongoing cost and guardrails remain acceptable.

## Two-minute interview demo

- **First 30 seconds** — Show the README chart and explain the one-pilot budget. Give the scope and identify the data as simulated.
- **Next 40 seconds** — Trace R00001 and show how SQL preserves the shipment denominator. Explain the difference between a cash refund and eroded margin.
- **Next 30 seconds** — Show the ranking and change the Excel assumption from 15% to 10%. Explain why the investment decision flips.
- **Final 20 seconds** — Describe the controlled size-guide test and the evidence you would need to claim a realized saving.
